1. Reproducibility — the central reliability question

Each evaluation face was executed twice, back-to-back, against the same frozen corpus and the same frozen query subsets (FlashRAG MANIFEST, seed=42). The comparison tool (scripts/compare_repro.py) flattens every field of both result files and reports any drift:

  • HotpotQA (91 corpus-answerable queries × 5 methods): all retrieval metrics identical. REPRODUCIBLE
  • 2Wiki (86 queries × 5 methods): all retrieval metrics identical. REPRODUCIBLE
  • Domain-50 (50 queries × 3 methods, stage1 k=150): identical. REPRODUCIBLE
  • PopQA verifier (200 queries, 1,600 chunk judgments, heuristic 0–8 rubric): identical. REPRODUCIBLE

Why it is deterministic by construction: frozen query subsets (SHA-256 manifest, seed=42), deterministic corpus sampling (sha256-stable ordering, verified byte-identical re-split), temperature-free heuristic scoring, and a frozen ingest snapshot. The one non-deterministic quantity — service latency under load — is reported separately and excluded from claims.

Interpretation (researcher view). This track surfaced and then fixed the paper's motivating failure mode — corpus-scale dominance in heterogeneous multi-KB deployments: small-KB recall@20 fell from 1.0 to ≈0 once a 12.5K-page generic corpus was co-indexed (mechanism: global BM25 candidates flooded by generic wiki pages, so the 8-document domain KB never entered the candidate set). Two mitigations were measured on the same frozen corpus: a 7.5× stage-1 budget recovers only partially (P@5 0.128), while the implemented defense — enlarged candidate pool (top_k × 8) plus KB-aware candidate quotas, now default — restores domain-query performance to small-corpus parity (P@5 0.420 vs 0.424 prior; routing 0.54 vs 0.52). The defense knobs are configurable (search.two_stage.stage1_pool_multiplier, kb_aware_candidates) with unit tests guarding the flood scenario.

6. Threats to validity (reviewer checklist)

  • Corpus subset. 12,588 of 18,068 planned pages (9/13 KBs) were frozen at evaluation time; the corpus-answerable filter excludes golden-page-missing queries (HotpotQA 9/100, 2Wiki 14/100) and is stated per-table. The remaining 4 KBs are auto-resumable; the same scripts re-run give full-corpus numbers.
  • Pilot sample size. n=91/86 per dataset; 2Wiki's headline p=0.006 is Bonferroni-safe, HotpotQA's gain is directional only. Full-scale runs (500–1,000) are the submission configuration.
  • Single backend instance. All runs share one backend; latency varies with co-located load and is excluded from claims. Metrics are load-invariant (§1).
  • Heuristic verifier tier. The 34.8%/77.4% numbers are the zero-dependency reproducibility tier, not the proposed LLM verifier.
  • No LLM in the retrieval loop. All reported numbers are embedding+BM25 only — no generation contamination; QA metrics will be reported separately with model+prompt frozen.
