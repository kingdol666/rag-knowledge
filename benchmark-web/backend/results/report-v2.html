1. System Architecture — NOT a RAG Retrieval Engine

Core Innovation: This system is a Knowledge Base Management Platform with MoE-style Query Routing. Unlike standard RAG which blindly searches all documents, QDCVR uses a multi-stage gating mechanism inspired by Mixture-of-Experts — only the relevant KBs are activated per query, and content verification independently judges result quality rather than trusting vector similarity scores.
Step 0: Query Analysis — Intent classification + entity extraction + query rewriting (declarative + keyword variants)
"BOPET薄膜应变诱导结晶" → Intent: 高分子材料加工 | Entities: PET/BOPET/结晶 | Rewrites: 4 variants
Step 1: MoE Router ← THE CORE INNOVATION
kb_list(lightweight=true) → 14 KBs scanned
Read KB descriptions → semantic match → Activate: 高分子双向拉伸文献库 (7,612 chunks)
IGNORE: AI-ML (691) · Embodied (407) · Energy (548) · Materials (714) · Chemistry (715) · ... (×9 more)
→ MoE Reduction: 30,000 → 7,612 = 3.9×
Step 2: Two-Stage Activated Search (仅选中KB内检索)
Stage1 BM25: 20 candidate docs → #1: Micromechanical-Modeling-PET (score 9.23)
Stage2 Vector Rerank: top 5 chunks → Stage2 Compression: 7,612 → 5 = 1,522×
Step 3: Content Verification (独立于向量分的裁决)
kb_doc_read(top-5, 3000 chars each) → 0-8 rubric scoring
Content > Vector — vector score is a hint, content score is the verdict

4. System Behavior Analysis — What the Benchmark Reveals

Vector Can Mislead — Why Step 3 Is Essential

Query R-06 "Adam优化器":
Stage1 BM25 correctly ranked Adam.md at #1 (score 9.88).
Stage2 Vector Rerank dropped Adam.md entirely — all 5 results came from a RAG survey paper instead.
Root cause: The RAG paper's "RL"+"reinforcement learning" vocabulary dominated the vector embedding space.

→ This is why Content Verification (Step 3) is mandatory: reading actual document content reveals the RAG paper is about retrieval augmentation, not Adam optimization.

Cross-KB Fallback Works Correctly

22% of queries (R-08, R-15) triggered auto-upgrade:
When BM25 Stage1 found results from only 1 KB, the system automatically supplemented with balanced vector search across all KBs.

R-08 (MXene): BM25 → Materials-Science only → fallback found Chemistry electrocatalysis + Polymer literature with MXene content.
R-15 (VLA): BM25 → Embodied-AI only → fallback found AI-ML papers with RL content.

→ This is the QDCVR→Enterprise auto-upgrade mechanism working as designed.

Content Gap Detection

R-17 "单原子催化剂": MoE correctly routed to Chemistry-Catalysis KB. Stage1 found electrocatalysis.md containing SAC content (Ni@VS₂, OER overpotential).

However, no dedicated "single-atom-catalyst.md" exists in the KB — the system returned the best available content (electrocatalysis with SAC sections).

→ This is correct behavior: the system found the closest match rather than returning nothing. Blind-spot declaration in Step 6 would note "no dedicated single-atom catalyst document exists."

Hierarchical KB Routing Limitation

高分子双向拉伸文献库 (7,612 chunks across 13 sub-KBs):
All 4 polymer queries activated the entire parent KB because sub-KB documents share the parent's ChromaDB collection.

MoE reduction is limited to 3.9× for this KB — the gate can't distinguish between PET/PVA/BOPP/PLA sub-domains at the routing level.

→ Architecture insight: sub-KB-level vector collections would enable finer-grained MoE routing, pushing reduction to 50×+ for large hierarchical KBs.
