\begin{abstract}
In changing document collections, a passage can match a query without
coming from a source that applies to the task. The Hierarchical Management
Retrieval System (HMRS) uses the same collection hierarchy to organise
documents and guide retrieval. At ingestion, an agent uses document text
to assign documents to collections and write descriptions. At query time,
an agent can consult the catalogue, inspect the selected collection and
retrieve source-linked passages. A rename-and-move probe found 18
vector entries where nine were expected; forced reindexing restored the
expected count, although the probe did not isolate the underlying fault. In
a scripted test on 72 in-domain questions, the reference route selected the
labelled collection on all 72 questions, but its evidence packs contained the
literal target string on only 37. Under the same route and initial search
policy, a configuration that combined scored document text, an additional
vector search and prioritised passage windows reached 52 target-string hits.
The text-coverage proxy remained higher in two same-question reruns,
although the configuration's components were not isolated. In fixed candidate pools,
verifier-score ordering yielded fewer top-five gold-document hits than fused
ranking. In a unified blind-scored comparison of native deployments, search scope and
source access differed; catalogue-first routing was not tested, and none of
the seven Holm-adjusted overall-score contrasts was significant. Taken together, these
results support an auditable management--retrieval path. They do not establish
improved claim-level grounding: collection choice, index presence, query
visibility, text coverage and answer support require separate checks.
\end{abstract}
