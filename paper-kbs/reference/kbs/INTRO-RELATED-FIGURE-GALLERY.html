① Before / After 动机图

引言最有力的开局：一张「没有我们的方法会怎样」，一张「有我们的方法会怎样」。两张图结构相同、只差一个模块，读者一眼看到贡献边界。

② 失败案例图

用一个具体 query 展示现有方法答错/答不全，配对话气泡、机器人图标与红绿高亮。这是把「问题存在」讲实的最快方式。

③ 范式对比图

上下或左右两套流程并排，配同一个真实问题，展示「旧范式哪里冗余、新范式哪里变干净」。适合承载 HMRS 的「向量召回 → 内容裁决」叙事。

④ 分类 / 背景图

Related Work 常用：把领域切成几类视角/输入形式/语义关系，或画一条时间轴。用图标 + 柔和配色，比大段文字更易读。

⑤ 结构 / 组织图

综述类论文在引言末尾给出全文地图；研究论文则给出 benchmark 或问题定义的结构。这一类图信息密度低但定位作用强。

⑥ 5 类引言/相关工作图型模板

图型什么时候用画法骨架（从上述真实图抽象）
T1 Before/After你的方法就是在流程里加了一个关键模块两张几乎相同的图并排或上下；左图标题 Without X，只有 User Query → LLM → Output；右图标题 With X，在中间插入虚线框圈住的模块（标注 Contribution），右侧仍保留原 LLM 但输入变成 c, x。灰阶即可。
T2 Failure Case要证明现有方法在真实问题上出错左右两栏共用一个 Premises/Question 框；改写一处关键条件（红色虚线高亮）；下方各放 chat bubble + 机器人图标；答案用 Unknown / No + ✓✗ 对比。对话气泡与图标让抽象逻辑变得可感。
T3 Paradigm Comparison你的贡献是改变整个检索/推理范式上下两条泳道：上方旧范式（冷色），下方新范式（暖色），左侧写明输入/线索，中间画同一条 KG/文档路径，右侧放同一个真实问题的 Response（部分正确 vs 完整正确，用绿/红标）。底部一句话写清 LLM 依据什么做选择。
T4 Taxonomy / BackgroundRelated Work 要交代领域版图2–6 个圆形或圆角框围成环/并列，每个框内放图标 + 短标题 + e.g., ... 例子；或画一条水平时间轴，节点上挂年份与事件方框。配色：每个类别一个柔和色（黄/蓝/绿），文字黑色。
T5 Organization / Dataset Structure引言末尾给出全文地图或 benchmark 定义综述：3 列箭头标题带 + 每列子条目 + 底部大括号汇合到挑战/建议。数据集：顶部一个真实案例框，下面 ① 旧数据集 ② 我们数据集 两条横向步骤链，底部放图标图例。
共同规律：引言图几乎不用跨栏大图，多为单栏或 2/3 栏；图注本身就是一个完整小例子（例如 An example of knowledge-grounded dialogue with responses from models. Text in orange denotes ...）；用红色/绿色只标注「错/对」，不用于装饰；图标（人、机器人、文档、数据库、剪贴板）比抽象方框更能降低理解成本。

⑦ 直接套用到 HMRS 论文

优先级建议图模板来源与落地画法
P0Figure 1：无内容验证 vs 有内容验证套 T1（FinBloom Fig.1/2）。左图 Without content verification：Query → 向量召回 top-1 (s=0.95) → LLM → 错误答案；右图 With content verification：召回后插入虚线框 Contribution: 0–8 Content Rubric，输出 c=3 ⇒ discard → not-found report。灰阶 + 一个强调色，两图结构严格对称。
P0Figure 2：一个具体失败 query套 T2（LGMT Fig.1/2 + PrivateLibrary Fig.1）。用一个域外问题，左栏展示「向量相似度最高但正文无关」的候选（红色虚线高亮），右栏展示 HMRS 读正文后 c≤4 并输出 not-found。底部各放一个 chat bubble 写模型回答，绿✓/红✗ 对照。
P0Figure 3：向量召回范式 vs 组织优先范式套 T3（FineGrained Fig.2）。上泳道冷色：整题 → 向量召回 → 候选堆叠 → 冗余/错配；下泳道暖色：按内容路由到领域库 → 逐候选正文证据核对 → 采用/fallback/丢弃。右侧放同一个真实问题的两种回答，标出哪个完整。
P1Related Work：检索系统版图套 T4（XAI meta-survey Fig.1 + LLM-KG Fig.1）。画 4–5 个圆形：向量检索 / 图检索 / 自我反思 RAG / Agent 工具检索 / 内容验证检索（突出自己），每圆放图标 + e.g., ... 代表工作。或画一条 RAG 演化时间轴（2020→2026）。
P1引言末尾：全文地图 + 数据集结构套 T5（Survey Fig.1 + MSDiagnosis Fig.1）。若正文篇幅允许，加一张论文组织图；实验章节前加一张「现有 QA 单跳 vs 我们六层题集」的结构图，明确每层考什么能力。
P1图注写法按 KBS 样本，每张引言图的图注写成 2–3 行小摘要，形如 An example of content-overrides-vector retrieval. Red denotes a high-similarity but content-irrelevant candidate; green denotes the accepted evidence.
P2不要做的事不要把方法部分的 ArchiMate 架构图搬到引言当 Figure 1（那是 Figure 4 的位置）；不要在动机图里用十几种颜色；不要用没有真实 query 的纯抽象方框。
一句话结论：你的论文最强的叙事恰恰是「向量很相似但正文不支持」——这在 KBS 里对应的是 T2 失败案例图 + T1 前后对比图的组合，比单纯再画一张系统架构图更能让评审在 10 秒内抓住贡献。
