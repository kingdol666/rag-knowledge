\section{Related work}
\label{sec:related}

\subsection{Knowledge management and document acquisition}

Knowledge-based systems combine language-model capabilities with curated
knowledge \citep{yang-kbs-llm-2025}. Public knowledge bases represent facts
using explicit ontologies \citep{auer-dbpedia-kb-2007,hoffart-yago2-kb-2013},
while enterprise content management governs the documents through which
organisations retain and share knowledge
\citep{paivarinta-ecm-2005,tyrvaainen-ecm-2006,nonaka-seci-1994,nonaka-seci-ba-2000}.
Metadata, tagging and human review affect which materials users can find and
trust \citep{park-metadata-quality-2009,golder-tagging-2006,mosqueira-rey-hitl-2022,barredo-arrieta-xai-2020}.
Text categorisation supports placement \citep{sebastiani2002machine}.
Layout-aware parsing and MinerU recover structured content for indexing
\citep{zhong-publaynet-layout-2019,huang-layoutlmv3-docai-2022,mineru}, while
near-duplicate detection and provenance help maintain the collection
\citep{manku-near-dup-2007,missier-prov-2013,cheney-provenance-2009}.
HMRS connects these operations by making the results of acquisition and
placement visible to the workflow that selects evidence.

Prior knowledge-platform research specifies responsibilities and interfaces
in reference architectures for journalism
\citep{ocaa2023software,gallofr2021jkpdesign} and implements complete
knowledge-grounded systems for dialogue, low-resource OpenQA, clinical
support and bank supervision
\citep{yang2024building,budur2024building,vito2025heliot,aarab2024system}.
Other systems integrate deployment constraints and expert knowledge
\citep{liao2026practical,garridomer2026gofai}, capture operator--function
models or instantiate domain ontologies \citep{hou2025method,ciatto2025large},
and support graph enrichment and engineering workflows
\citep{mohamed2026orchestra,liu2026automatin,chen2026enhancing,sorokin2023sigopt}.
HMRS takes this systems perspective to the changing document collection.
Its focus is the state that a deployed evidence workflow reads and that an
operator can inspect after a management operation.

RAG uses retrieved passages to inform generation \citep{rag-lewis}. Dense
retrieval ranks passages in a learned representation space \citep{dpr}; BM25
uses lexical signals \citep{bm25}. Enterprise architectures combine semantic
retrieval with vector storage and LLMs \citep{ghali-kbs-retrieval-2025}.
Hybrid search combines ranking signals, for example with reciprocal-rank
fusion \citep{rrf-cormack}, and BGE-M3 provides multilingual and
multi-granularity embeddings \citep{bge-m3}. Structured retrieval organises
the units a ranker searches. GraphRAG builds entity graphs and community
summaries \citep{graphrag}; LightRAG updates a dual-level graph incrementally
\citep{lightrag}; RAPTOR recursively groups text into a cluster tree
\citep{raptor}; and RMR-SST represents multimodal engineering documents as
semantic trees \citep{li-kbs-rmrsst-2026}. Proposition-level indexing,
late chunking and hierarchical semantic chunking make different choices
about what each unit retains
\citep{chen2024dense,gunther2024late,shen-kbs-teierag-2026}.
Table~\ref{tab:related-comparison} locates HMRS among these designs. Its
hierarchy represents collection ownership and document structure, so a
query reads a maintained record of which collections and documents exist.
Index maintenance complements this hierarchy by keeping passages reachable
after document changes \citep{singh2021freshdiskann,xu2023spfresh}.

Distributed IR selects collections from relevance estimates before searching
them \citep{callan1995searching,si2003redde}. HMRS applies the same
select-then-search principle to collection and document descriptions that
operators can maintain. Tool-using agents can choose and iteratively refine
what they retrieve \citep{react-yao,toolformer}; MCP provides standard
interfaces to these tools \citep{mcp}. Modular and agentic RAG work studies
how the resulting workflows combine retrieval calls
\citep{modular-rag,singh-agentic-rag}. DeepRead illustrates structure-aware
agent access within a document by indexing paragraphs with section
coordinates and reading selected sections \citep{deepread}. HMRS gives
an agent a catalogue and shelf to determine which documents to open, then
exposes document and passage access through the same tool layer.

Recent knowledge-based retrieval systems study engineering design and
private code libraries \citep{siddharth2024retrieval,zan2025private},
soft-prompt tuning and semantic query expansion
\citep{peng2024soft,massai2023evaluatio}, and LLM-guided graph exploration
\citep{dai2025large,huang2025prompting,tao2025fine}. Systems for financial
grounding and multi-agent answer generation show how retrieved evidence is
used downstream \citep{sinha2026finbloom,saadaoui2025coordinat}. HMRS
makes the upstream document state available for inspection alongside that
retrieval and answer process.

\subsection{Verification, correction and abstention}

MemGPT, Mem0 and A-MEM maintain agent interaction records and notes
\citep{memgpt,mem0,amem}, and continual-learning work studies complementary
memory stores \citep{wu2025informati}. HMRS maintains a corpus of source
documents and the descriptions, ownership and indices used to find them.
Knowledge organisation standards such as SKOS \citep{skos} and Dublin Core
give conventions for vocabularies and descriptive metadata. At ingestion,
the HMRS workflow derives descriptions and tags from document content.

Self-RAG and CRAG assess evidence or correct retrieval during generation
\citep{selfrag,crag}; FLARE triggers retrieval as more evidence is needed
\citep{flare}. Selective prediction under domain shift, uncertainty
reporting, ontology-grounded retrieval and citation verifiability supply
methods for handling incomplete evidence
\citep{kamath,feng-abstain,yin-knowwhat,cyberbot,liu-verifiability,gao-citations}.
EPRAG diagnoses evidence states to choose among response, clarification and
abstention in enterprise retrieval \citep{kinalioglu-kbs-eprag-2026}.
HMRS makes verification a server-side operation. The gate fetches
candidate text, scores passages and returns surviving text with provenance,
so an agent can inspect the source material behind the result.

Judge studies report preference bias, variable agreement and ranking
instability \citep{zheng-llmjudge,sun-urara,panickssery-selfpref}.
Outcome-based verification can also reward flawed reasoning
\citep{lightman-verify}. Related systems work examines explainability,
logic-grounded reliability tests and graded assessment
\citep{saeed2023explainab,zhou2026lgmt,hou2025msdiagnos}. These findings
motivate separate measurements for evidence admission, candidate order and
answer-stage reporting.

\subsection{Research gap}
\label{sec:gap}

The literature offers methods for managing documents, selecting collections,
ranking passages and checking evidence (Table~\ref{tab:related-comparison}
and Supplementary Table~S11). HMRS makes the connections among these
operations inspectable. It records the collection that owns a document,
exposes the descriptions that a query uses to find it, and preserves source
references when passages reach the answer workflow. Its evaluation therefore
asks where the evidence path succeeds or fails, from post-ingest state and
catalogue visibility through candidate selection and verifier ordering.
