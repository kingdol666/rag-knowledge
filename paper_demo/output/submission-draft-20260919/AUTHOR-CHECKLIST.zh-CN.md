## 二、强烈建议在真正提交前补齐，但不是伪称 CFP 规定的指标

### A. 一次冻结版本的端到端演示记录
保存源码 commit、当前 working-tree 差异、日期、操作系统/硬件、解析器与 embedding 模型版本、agent harness、实际解析的 LLM 提供方/模型 ID、关键参数、缓存状态、提示词/skill 版本和语料清单。

至少从干净会话走通三条路径：新 PDF 的组织与全部分片检查；有证据的回答；无足够证据的报告。原始工具调用、读取偏移/返回文本、每次 gate 判断、回退和最终回答应可以关联到同一 run ID。不能事后用手写报告替换实际日志。

这不是要求为 Demo 添加大规模 SOTA 评测，而是让视频、界面、代码和论文对应同一个可复现的系统状态。

### B. 选择并统一实际演示的入口/策略
当前代码审计发现：网页聊天注入阈值与 packaged skill 不一致；普通 HTTP 检索不强制 gate；MCP 创建多分片时 wrapper 的标签/索引处理只覆盖首次返回的文档。稿件已限定为 agent-assisted 流程并要求逐分片检查，**没有替你修改业务代码**。

可选择在演示中始终使用已加载 skill 的 MCP agent，并显式展示逐分片补全与状态检查；若要承诺统一网页自动协议或自动全分片处理，应先修复实现并补回归验证，再修改论文。不要把修复后的能力提前写入本稿。

### C. 若仍希望主张效果或速度优势，需要新证据
现有固定改写包含预期答案信息；A/B/C 的证据窗口、调用方式、缓存和模型配置不一致；部分统计与当前原始答案不匹配。因此本稿删除了 10/10 正确率、速度优势和“两次失败后救回”等结论。

如需恢复这类主张，必须冻结统一设置、避免答案泄漏、保留 chunk-to-document 元数据与端到端时间、记录缓存与实际模型，并提供独立答案评判和可复算的结果。不能通过换一种措辞恢复原数字。
