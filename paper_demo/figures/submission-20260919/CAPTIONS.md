# Proposed figure captions and scope notes

These are integration suggestions only; the manuscript TeX remains owned by main.

## Figure 1 — concept

Process comparison for the shared BQ02 NISQ question. The current dense-RAG reproduction scripts use approximately 800-token fixed windows, request ten dense candidates, and pack two excerpts in the saved records within a 4,000-character evidence budget before one generation call. Missing source-document provenance is a logging/adapter limitation of this reproduction, not a property of dense retrieval. The agent-executed QDCVR skill reads section-addressed candidate text and applies an LLM-self-assessed 0–8 rubric with pass threshold ≥6. Initial scores ≥6 permit direct answering. Score 5 is retained as a P1 backstop while fallback seeks stronger evidence; scores ≤4 are discarded. After fallback and new-text reading/rechecking, P0 ≥6 supports a cited answer, and usable P1 score 5—including a retained initial backstop—can support a qualified answer with attribution and explicit limits. Only no usable P0/P1 evidence yields a scoped not-found report. The diagram contrasts configurations, not matched accuracy or efficacy.

## Figure 2 — architecture

Platform capabilities and the packaged agent workflow. Web HTTP access and CLI setup/service management are distinct from the agent's MCP adapter; these surfaces share backend/storage capabilities, not an automatically enforced retrieval policy. Left: agent-assisted ingestion uses parsing and deterministic storage/indexing primitives, with the agent reading content, routing it within the five-base demonstration corpus, and selecting/propagating tags. This is not an automatic-all-uploads or all-parts-tagged guarantee. Right: the agent-executed QDCVR skill rewrites a query, recalls balanced vector candidates, reads their text, and applies the 0–8, ≥6 content gate. Initial ≥6 supports direct answering; initial 5 is retained as a P1 backstop and ≤4 is discarded, with both triggering fallback and reading/rechecking. Post-fallback P0 ≥6 supports a cited answer, while usable P1 =5 supports a qualified answer with attribution; not-found is reserved for no usable P0/P1 evidence. The five-section answer structure retains sources, confidence and blind spots. File-tree/YAML data are mutable metadata; saved benchmark evidence/judgment JSON artifacts are separate, not automatic per-query audit logs. The depicted threshold is the packaged skill policy, not a claim that every web/chat prompt or HTTP endpoint enforces it.
