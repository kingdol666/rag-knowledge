\begin{figure*}[t]
\centering
\includegraphics[width=0.84\textwidth]{../figures/fig1_architecture.png}
\caption{Architecture of \sys{}. Clients (web console, CLI, MCP agent
harnesses) reach an agent-side protocol layer served by the \texttt{kb-mcp}
server, which fronts FastAPI services for parsing, content classification, tag
propagation, retrieval and the experience lifecycle, over ChromaDB with BGE-M3
vectors, a Neo4j graph, and a YAML file tree that doubles as the audit log. The
orange trace follows one real benchmark query: query rewrite, 1.5\,s vector
recall across the category bases, a content gate that scores the candidate text
7/8 and exits early, and a five-section cited answer. Storage is written through
a single path and read directly by retrieval, so search adds no load to the
service tier. The same capability set is published twice, as REST endpoints for
the console and as 41 \texttt{kb\_*} MCP tools for agents.}
\label{fig:arch}
\end{figure*}

\begin{figure*}[t]
\centering
\includegraphics[width=0.84\textwidth]{../figures/fig2_ui_composite.png}
\caption{The deployed console, captured live. Panel~(1) lists the five
content-classified category bases with their indexed-document counts, beside
three reproduction indices that were built by chunking rather than by reading;
panel~(2) is a complete retrieval session, in which the NISQ question returns
the gold paper first at $0.62$ fused BM25\,+\,vector similarity with the owning
base, document and part printed on the hit card; panel~(3) shows the part and
tag model, where a long paper becomes \texttt{(part k of N)} cards that inherit
their document's tags; panel~(4) is the relation graph over 165 documents, 321
relations and 27 tags. No interface element is mocked, and every count
shown here matches the benchmark artifacts.}
\label{fig:ui}
\end{figure*}
