# nuwa → SOUL Seed Mapping — Landing Rules for Nüwa Outputs

> Used together with the butian skill: after nuwa distillation completes, the outputs are
> converted by nuwa_to_seed.py into a Butian seed package, which is landed as a SOUL persona
> via ragctl soul distill. This document is the authoritative section-level mapping.

## 1. Dual-Output Model

```
nuwa distillation complete
  ├─ Output A: [person]-perspective/SKILL.md      ← standalone runnable person Skill (open-source distribution)
  ├─ Output B: references/research/0X-*.md        ← raw 6-dimension research material (self-contained)
  └─ Output C: soul-seed/ (generated by the converter) ← Butian seed package (SOUL landing input)
       ├─ meta.json  persona.md  work.md  values.md
```

Output A is always generated (nuwa's core job); Output C is converted in one click by the
butian dispatcher — no duplicated effort.

## 2. Section → Seed → SOUL Document Mapping

| nuwa SKILL.md section | → seed file | → SOUL document | Notes |
|---|---|---|---|
| `## Identity Card` | persona.md | soul-definition.md appended section | Who I am / starting point / current state → identity positioning |
| `## Expression DNA` | persona.md | soul-definition.md appended section | Sentence patterns / vocabulary / rhythm / humor / certainty → language style |
| `## Role-Play Rules` | persona.md (truncated at the exit-the-role line) | soul-definition.md appended section | Output discipline / flag inference on unstated topics |
| `## Honest Boundaries` | persona.md | soul-definition.md appended section | Knowledge boundaries / research cutoff date |
| `## Answer Workflow (Agentic Protocol)` | work.md | thinking-style.md appended section | Do the homework first, then answer → reasoning mode |
| `## Core Mental Models` (### Model N:) | work.md | thinking-style.md appended section | Thinking lenses (the triple-validated ones) |
| `## Decision Heuristics` | work.md | thinking-style.md appended section | Judgment rules |
| `## Intellectual Genealogy` | work.md | thinking-style.md appended section | Intellectual sources and position |
| `## Person Timeline (Key Nodes)` | work.md | thinking-style.md appended section (background) | Contextual knowledge |
| `## Failure Modes and Fallback Tree` | work.md | thinking-style.md appended section | Degradation rules |
| `## Values and Anti-Patterns` | values.md | values.md appended section | Constitutional-layer values (ragctl --values) |
| `## Appendix: Research Sources` | (stays in the skill directory) | — | Provenance basis; not included in the seed |
| frontmatter `name` | meta.json.slug | soul-<slug> library name | name with the -perspective suffix removed |
| frontmatter `description` | meta.json.impression + tags | KB description + domain_labels | First sentence becomes the impression; model names become routing labels |
| Identity Card "Who I am" | meta.json.display_name | KB name / display | Truncate to 30 characters |

## 3. Routing-Label Generation Rules (domain_labels)

1. display_name (e.g. "Steve Jobs")
2. slug (e.g. "steve-jobs")
3. Mental-model names (### Model N: headings, up to 8 in total)
4. Optional explicit additions via --labels

At landing time, ragctl defaults to the first 3 + the first 12 characters of the
impression → routing: "which questions get routed to whom" is matched by persona name +
model names, which is more precise than generic labels.

## 4. Constitutional-Layer Handling of values.md

- nuwa's "Values and Anti-Patterns" → values.md appended section; at **creation time** it is
  fused into the template values.md via `ragctl soul distill --values values.md`
- The template's generic research values (authenticity first / honest boundaries / knowledge
  humility) stay in the first half of the document; the distilled values are appended after
  → the two sets of values sit side by side and are referenced together in training/evaluation
- **Immutable after creation** (the constitutional layer is read-only); adjustments go through
  soul_reflect drift reports + human decisions

## 5. Topic-Skill Variant (xx-framework, not a person)

- No Identity Card → display_name falls back to the frontmatter name
- No Expression DNA → persona.md contains only role rules / boundaries (if present)
- No Values and Anti-Patterns → no values.md is produced (ragctl is not passed --values)
- All other mappings unchanged

## 6. Validation Checklist (after conversion)

- [ ] persona.md / work.md are non-empty
- [ ] meta.json parses; slug carries no -perspective suffix
- [ ] values.md exists (person type)
- [ ] ragctl soul distill lands successfully (docs_created=4 + profile)
- [ ] visible in soul_list; domain_labels = persona name + model names
