## 本轮抓到并修复的缺陷

**① usePDFParser 裸 fetch 无鉴权头（真缺陷，已修）**
`web/composables/usePDFParser.ts` 的 4 个调用点用原生 `fetch()` 绕过了全局 `$fetch` 鉴权拦截器——在启用 token 校验的部署上，解析入库必 401（UI 表层症状："Failed to start streaming"）。修复：新增 `authHeaders()`（与拦截器同源的 localStorage key + Bearer 形态）接入全部 4 个调用点。复现→修复→UI 重跑通过。

**② 索引时序（工作流特性，已按设计路径补救）**
解析入库只写盘不建检索索引：UI"重建索引"（增量）补齐向量层；BM25/两段式需 `index-document` 或全量重建。补索引后两段式 5 hits。改进建议：解析入库成功后自动触发该文档的 index-document。

## 演示过程发现的其他小事

- OMP 检索作业中出现 write 工具徽章：agent 自有暂存行为，产物在其会话目录（~/.omp），仓库零副作用（git status 核实）。
- toast 出现原始 i18n key（"fs.parseResultMsg"/"search.rebuildSuccess"）——翻译缺行，不影响功能。
- 浏览器旧 token 失效会踢登录页：属预期安全行为，重新登录即可。
